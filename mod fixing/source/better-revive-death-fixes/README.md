# Better Revive death and compass fixes

The active pack JAR is `Better Revive - 2.2.0 - NeoForge - 26.2-MultiGraveFix-Java25.jar`. The user's full-pack single-player log clarified the second-death failure: the old grave survived, while each new grave became a temporary collection crate and expired immediately. The log showed a new grave and compass followed within one second by "Your collection crate expired. Uncollected items were deleted." The saved world has a zero-second collection phase. Upstream `ModEvents` marked a new grave temporary whenever `GraveRegistry.hasActiveGraves(owner)` was true; normal respawn then called `convertToCollection` on temporary graves. The repack now makes both death-grave creation paths produce ordinary independent graves with their own deadlines. This patch changes `ModEvents.class` only relative to the preceding renamed JAR. The personal world and separate desktop server were not modified.

The prior JAR already contains the grave guard, XP fix, retained-gear rule, and five-minute expiry. The active repack modifies three original classes and adds `DeathFix`.

Root causes:
- PlayerRevive leaves a downed player alive. On a second lethal hit or give-up, Better Revive captures the grave and then allows PlayerRevive's real death to complete. Entering Better Revive's downed state and trying a nested lethal hit failed for give-up because PlayerRevive had already set health to zero; the player could remain beside the grave with 1 health and 6 food. Respawn clears persisted downed state and the PlayerRevive bleeding flag.
- The previous death patch replaced `ModEvents.onPlayerRespawn` and accidentally removed the earlier `KeepGear.onRespawn` hook. Retained hotbar and armor were serialized under `NeoForgeData.better_revive_keep_gear` but never restored. The respawn handler now calls the gear restoration hook before clearing death state.
- Better Revive's final-damage defaults include `minecraft:lava`, so lava death bypassed grave creation. Effective damage classification now treats lava as a grave death, while `minecraft:out_of_world` and the below-world rule remain final. The bytecode patch must replace the second `List.contains` call in `isConfiguredFinalDeath`: the first checks dimensions. The safe-placement search reaches farther to find a shore and can place a grave in air immediately above lava when no nearby land exists.
- A missing grave could leave a registered location and an active Grave Compass. Online compasses are checked each second against registration and the stored deadline; expired or unregistered compasses are removed. Old graves retain their stored deadlines.
- The Grave Compass now occupies the final hotbar slot (slot 8). If that slot holds an item, the item moves to an available main-inventory slot. Compass placement and the periodic slot check use the same rule, so neither can overwrite a retained hotbar item.
- Grave selection now uses the newest unexpired grave. Older graves remain registered with their own contents and deadlines, and the compass follows a remaining grave after collection. A missing text-display entity no longer aborts grave creation. Subsequent death graves are no longer flagged temporary merely because the owner has an active grave.

Compile `PatchDeathFix.java` for Java 25 against ASM and ASM Tree, run it on the five original classes, compile `DeathFix.java` for Java 25 against the patched classes plus the Better Revive, PlayerRevive, Minecraft 26.2, and NeoForge libraries, then run `repack.py` against the previous grave-guard JAR. The separate desktop server was not changed.

Runtime check (2026-10-15): an isolated NeoForge 26.2.0.90 flat-world server and client loaded Better Revive, Better Revive X PlayerRevive, PlayerRevive, and CreativeCore. A first generic lethal hit left the player downed with no grave; the second caused one real death and a grave. Replacing the live grave with air was repaired on the next tick. With a 30-second test grave duration, the grave and compass both expired. The initial build still treated lava as final because it patched the dimension check; after correcting that bytecode target and rebuilding, a lava damage hit followed by a lethal hit produced a grave and matching compass. Two `out_of_world` hits caused final death with no grave or compass. The project JAR and isolated copies now contain the corrected build. These command-driven checks do not cover every multiplayer interaction or natural lava pool shape.

Runtime regression check (2026-10-16): the isolated flat server/client also loaded Curios and Better Revive X Curios. Before this revision, a sword saved in `better_revive_keep_gear` was absent after respawn. A temporary test-only command invoked `PlayerReviveServer.kill`, the same method used by PlayerRevive's give-up packet; before this revision it left the player alive near the grave with 1 health and 6 food. With the revised JAR, both a second lethal hit and the give-up method caused one real death, left the retained sword in the hotbar and chestplate equipped, restored 20 health and 20 food, and placed only the non-retained emeralds in the grave. The test-only command JAR is in the ignored isolated test directory, not the pack. The active pack and local fixed-pack copy use the same filename with new contents; the separate desktop server and personal Minecraft profile were not modified.

Final full-hotbar check (2026-10-16): all nine hotbar slots held different items before a scripted give-up. After respawn, slots 0–7 still held their original items; the Grave Compass occupied slot 8; the displaced stone from slot 8 moved to main-inventory slot 9. Chestplate and offhand shield stayed equipped, health and food returned to 20, and only the emeralds were stored in the grave. A test-only call to the grave's inventory restore returned the emeralds without clearing the retained hotbar, armor, or offhand; the compass remained in slot 8 and the stone remained in main inventory. The test-only probe JAR was not packaged.

Better Respawn compatibility check (2026-10-16): the same isolated NeoForge 26.2.0.90 client and dedicated flat server loaded Better Respawn 2.0.6 with the six Better Revive/PlayerRevive/Curios dependencies and the temporary probe. Better Respawn used its default 128–256 coordinate range and placed the player about 283 blocks from a first grave and about 315 blocks from a second grave. The first death followed a lethal hit and PlayerRevive give-up; the second used the give-up method with a full hotbar. Both deaths completed with full health and food. In the full-hotbar case, slots 0–7, chestplate, and offhand shield remained equipped; the compass occupied slot 8 and displaced stone moved to main inventory slot 9. The distant grave chunk unloaded, then loaded again when the player returned. It held only the 16 emeralds and retrieval returned them without losing any retained gear; the displaced stone moved to main inventory slot 10. This verifies the server-side death, respawn, compass target, and grave inventory flow. It does not replace a manual multiplayer or visible compass-direction check. The isolated world's grave duration was 30 seconds for the regression run; the pack default remains five minutes.

Multiple-grave regression (2026-10-16, preceding build): the isolated world used a 300-second grave duration with Better Respawn installed. Two scripted deaths at different positions registered two graves with separate item stacks. Before the compass fix, the original tick handler repeatedly returned the compass to the oldest non-temporary grave. With that repack, it pointed to the newest grave. Retrieving the newer grave first changed the compass to the older grave; retrieving the older first left the newer target intact. Both orders returned both item stacks and removed the compass when no graves remained. Two deaths at the same position placed distinct graves at (0,-60,0) and (-1,-60,-1). Before the display guard, the second creation logged a null text-display exception and reported fallback to vanilla death despite a registered grave. With the guard, both graves remained physical, held separate emerald and diamond contents, and could be retrieved. A full-hotbar give-up after the change still retained slots 0–7, chestplate, and offhand, placed the compass in slot 8, and moved the previous slot-8 item to main inventory. These isolated checks did not catch the temporary-grave conversion after normal respawn in the full pack. All changed class files have Java 25 class version 69. The latest single-player world inspected read-only had a saved 180-second grave duration, which overrides the 300-second JAR default; that personal world was not edited.
